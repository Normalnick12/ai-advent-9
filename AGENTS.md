# AGENTS.md

## Общий подход

- Это учебный AI Advent проект, состоящий из отдельных заданий в папках `day-XX-*`.
- Размещайте каждое задание в отдельной папке `day-NN-short-name`.
- По возможности выполняйте техническую работу самостоятельно: создавайте и изменяйте файлы, устанавливайте зависимости, запускайте приложение, тесты и другие проверки.
- Не усложняйте решения без необходимости. Для учебных заданий предпочитайте минимальную и понятную реализацию.
- Используйте актуальные официальные OpenAI API и SDK, если заданием не требуется иное.
- Перед завершением проверяйте синтаксис и структуру изменённых файлов.
- Никогда не добавляйте API-ключи, токены и другие секреты непосредственно в исходный код.

## Секреты и локальные файлы

Никогда не добавляйте в Git:

- `.env` и другие файлы с секретами;
- `.venv` и `venv`;
- `__pycache__` и Python-байткод;
- IDE-файлы;
- локальные кэши;
- API-ключи и токены.

Перед каждым commit проверяйте изменения на наличие секретов.

## Git workflow

Не выполняйте commit и push автоматически после каждого изменения.

Выполняйте commit и push, только когда пользователь явно просит:

- `Заверши Day XX`;
- `заверши текущее задание`;
- `commit and push`;
- или прямо просит сделать commit и push.

При завершении задания:

1. Выполните `git status`.
2. Просмотрите `git diff` и состав изменённых файлов.
3. Убедитесь, что секреты и локальные файлы не попадут в commit.
4. Запустите разумные для текущего задания проверки: тесты, линтеры и/или само приложение.
5. Если обнаружена ошибка, сначала исправьте её и повторите проверки.
6. Добавьте в Git только необходимые файлы.
7. Создайте короткий понятный commit message на английском, отражающий суть задания.
8. Выполните обычный `git push` в текущую upstream-ветку.
9. Никогда не используйте `git push --force` без явного запроса пользователя.
10. Не выполняйте `commit --amend` и не переписывайте историю без явного запроса пользователя.
11. После push снова проверьте `git status`.

В финальном отчёте укажите:

- какие проверки были выполнены;
- commit message;
- commit hash;
- ветку;
- результат push;
- чистый ли рабочий каталог.

Если commit или push невозможен из-за авторизации, sandbox, сети или прав доступа, не пытайтесь обходить безопасность. Кратко сообщите причину и команду или действие, которое требуется от пользователя.

## README

При выполнении каждого задания поддерживайте `README.md` соответствующей папки в актуальном состоянии. Укажите:

- необходимые зависимости;
- как настроить окружение;
- как запустить;
- какие переменные окружения требуются.

Никогда не помещайте реальные значения секретов в README.
