# Day 22 — Первый RAG-запрос

## Суть эксперимента

Локальный CLI выполняет question → embedding → cosine search → Top-5 →
context с источниками → ответ модели. Используется сохранённый structure-aware
индекс Day 21 без повторной индексации. Для десяти вопросов сравниваются direct
и RAG: вопрос, общая инструкция и generation settings одинаковы; меняется
только наличие найденного project context.

## Что проверяет

- Как baseline находит факты для пяти локальных, трёх cross-source и одного
  сложного вопроса; отдельный negative control спрашивает отсутствующие RPO/RTO.
- Где возникает ошибка: retrieval, сборка context, generation или неподдержанные
  утверждения. Попадание файла в Top-5 само по себе не подтверждает наличие факта.
- Сохранение полной цепочки и повторный просмотр результатов без API calls.

## Результаты

29 сентября 2026 выполнен один eval Q01–Q10: 10 query embeddings, 10 direct и
10 RAG generations завершились технически успешно. Повторов не было. Вопросы
и expected facts сохранены в [questions.json](questions.json), ответы и ручной
разбор по каждому факту — в локальном evidence; команды просмотра ниже по ссылке.

В этом запуске RAG покрыл expected facts всех пяти локальных вопросов и Q09.
Для Q07–Q08 retrieval дал неполный context: в Q08 даже попадание нужного файла
не обеспечило нужные факты. В ответах Q06–Q08 обнаружены неподдержанные
обобщения или перенос правил между сценариями. Потери полных chunks при сборке
model input не обнаружено. Direct в основном признавал недостаток сведений,
а в Q09 предложил поведение, противоречащее project contract.

В Q10 Top-5 непустой, но значений RPO/RTO в нём нет; оба ответа признали
недостаток информации. Это no-answer case, а не доказательство плохого поиска.
Вспомогательный `source_path_hit@5` — 8/9 положительных вопросов; он не измеряет
наличие фактов. Выводы относятся только к этим десяти вопросам и одному run,
не доказывают превосходство RAG или оптимальность Top-5/structure-aware.
