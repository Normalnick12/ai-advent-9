# Day 08 — Работа с токенами

## Суть эксперимента

Лаборатория делает видимыми стоимость и ограниченность full-history агента:
каждый ход снова отправляет всю подтверждённую историю. Во всех стадиях Day 08
используется одна `gpt-4o-mini` с окном 128000 tokens; Day 06/07 сохраняют свою
конфигурацию. История принадлежит backend и сохраняется в отдельной SQLite-базе.

Новое сообщение и сохранённая история считаются provider отдельно, без
инструкций. Полный preflight считает точный контекст с инструкциями. Эти три
измерения **не складываются**. Actual input/output приходят после generation;
«Оценочная стоимость хода» считается только по actual usage и фиксированным
тарифам, а отсутствие данных не означает нулевую стоимость.

## Что проверяет

- Короткий факт, короткий вопрос, видимый длинный текст и снова короткий вопрос
  показывают, как небольшой новый запрос соседствует с большой историей.
- Таблица последних попыток показывает actual input/output и оценочную стоимость
  текущего запуска; эти метрики не сохраняются как billing journal.
- Отдельная подготовка создаёт один новый тестовый user message: заголовок,
  повторы строки `0123456789 abcdefghijklmnopqrstuvwxyz` с LF и просьба кратко
  ответить. Provider count должен подтвердить 132000–160000 tokens. Только
  отдельное подтверждение разрешает один настоящий overflow generation request.
- Overflow probe не записывается в историю при любом исходе. Compression,
  trimming, automatic truncation и переключения модели нет.

## Результаты

В ручном live прогоне, подтверждённом пользователем, четыре обычных хода
завершились успешно. Actual input вырос **110 → 150 → 3174 → 3196 tokens**:
после длинного обмена даже короткое новое сообщение отправлялось вместе с
большой историей. UI показывал оценочную стоимость; ответы и счётчик ходов
были корректны.

Настоящий overflow request после отдельного подтверждения был отклонён
provider: preflight **137924 tokens** при лимите **128000** (**107.8%**).
Actual usage отсутствовал, UI показал «нет данных». История осталась прежней,
счётчик — **4**; сокращения истории, replay и записи oversized payload не было.

После полного restart backend session восстановилась из SQLite без rejected
payload. Следующий короткий ход успешно вспомнил цвет «янтарный»: standalone
history **3117**, новое сообщение **17**, preflight и actual input **3219**,
output **6** tokens; оценочная стоимость **0.00048645 USD**. Счётчик вырос
**4 → 5**. Runtime таблица попыток после restart не восстановилась, как и
предусмотрено; подтверждённая история сохранилась.

Теоретически при примерно постоянном размере новых сообщений и ответов текущий
контекст растёт примерно линейно, а cumulative processed input full-history
calls может расти квадратично. Длинный ответ оплачивается как output сейчас и
попадает в будущий input. Prompt caching может менять цену отдельного хода,
поэтому её строго монотонный рост не обещается; сумма стоимости новых платных
calls растёт. Это расчётная модель, не измеренный результат разговора.

Зависимости, настройка и запуск описаны в [backend](../backend/README.md)
и [Android](../android-app/README.md). `OPENAI_API_KEY` задаётся только на backend.
