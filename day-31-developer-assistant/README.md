# Day 31 — Ассистент разработчика

## Суть эксперимента

Команда `/help` отвечает на вопросы о реальном проекте. RAG ищет по корневому
README, описанию структуры и README компонентов; OpenAI формирует ответ с
проверяемыми цитатами. Текущая Git-ветка получается отдельным локальным
MCP-инструментом через stdio и показывается рядом с ответом.

## Что проверяет

- Ответы на основании актуальной документации и честный отказ при нехватке данных.
- Настоящие MCP discovery и вызов инструмента, отдельные от генерации модели.
- Проверяемые источники и диагностику поиска через `--trace`.

## Результаты

Индекс построен по пяти разрешённым документам: 87 фрагментов,
`text-embedding-3-small`. Повторная сборка неизменившегося корпуса не вызывает API.
Генерация использует Responses API и `gpt-5.6` (фактически `gpt-5.6-sol`).

Пройдены 160 offline/integration и регрессионных проверок. В итоговом live-прогоне
три ответа о компонентах, RAG CLI и Android-тестах подтверждены источниками;
вопрос о недокументированных SLA и production on-call вернул `insufficient_context`.
Во всех четырёх случаях выполнены настоящее MCP discovery и вызов Git-инструмента.
После добавления компактного `--trace --trace-format text` отдельно прошли
38 CLI/MCP-проверок; JSONL по умолчанию сохранён. Наборы тестов пересекаются,
поэтому их количества не складываются.

При приёмке исправлены ошибки строгой JSON schema и неточного копирования цитат:
модель выбирает идентификаторы evidence, а источники и дословные цитаты берутся
из отправленного контекста. Четыре вопроса подтверждают этот сценарий, но не
гарантируют качество любых ответов. Подробности — в
[отчёте проверки](../openspec/changes/archive/2026-10-16-day-31-developer-assistant/validation.md).

Настройка и запуск описаны в [backend](../backend/README.md)
и [scripts](../scripts/README.md). `OPENAI_API_KEY` используется только в backend.
