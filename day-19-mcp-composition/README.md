# Day 19 — Композиция MCP-инструментов

## Суть эксперимента

После одного запроса модель сама выбирает три отдельных MCP tools: получает полный
список версий Google Maven, передаёт его для детерминированного отчёта и сохраняет
отчёт в JSON на сервере. Days 17–18 сохраняют прежние endpoints; Day 18 scheduler
в этой цепочке не участвует.

## Что проверяет

- Порядок трёх вызовов и точность передачи полных объектов между ними.
- Содержимое файла через независимое чтение и verifier.
- Точность финального ответа отдельно от исполнения цепочки.

## Результаты

Offline, deployment/readiness и pre-live прошли. Полный payload — 130 версий,
2079 canonical UTF-8 bytes; бюджет ответа 16384 токена с запасом, deadline 600 s.
Offline-контроль с этим списком прошёл три отдельных MCP-вызова и проверку файла.

24 сентября 2026 выполнена ровно одна live-попытка с auto, без retry/repair.
Получены три completed MCP calls lookup → summarize → save. Оба полных перехода
и детерминированный расчёт — PASS. Отчёт содержит 130 версий, последние элементы:
`1.19.0-rc01`, `1.19.0`, `1.19.1`. Модель вернула те же факты.

Операторский экспорт подтвердил семь серверных событий и прочитанный файл
размером 415 bytes. Независимый verifier дал PASS отдельно для tools, порядка,
обоих переходов, расчёта, файла и финального ответа. Chain и full acceptance — PASS.
Первые NOT_PROVEN сохранены: тогда журнал и disk bytes были недоступны проверяющему.
Это результат одной попытки, а не доказательство устойчивости всех будущих запусков.
