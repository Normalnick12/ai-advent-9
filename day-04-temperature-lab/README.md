# Day 04 — Влияние temperature

## Цель

Изучить, как temperature влияет на разнообразие ответов модели, сравнив
значения **0 / 0.7 / 1.2** на одном запросе. Отделить формальное соблюдение
требований от субъективной оценки качества названий.

## Что реализовано

- Android-лаборатория с тремя ответами на один prompt и метриками tokens/latency.
- Benchmark с автоматической проверкой требований и счётчиками уникальных названий.
- История прогонов в текущей сессии и свободный режим для собственного запроса.

## Эксперимент

В каждом прогоне выполняются три вызова. **Единственная переменная — temperature**:
текст запроса, модель, reasoning, лимит токенов и формат ответа одинаковы.
Для наблюдения разнообразия benchmark запускается несколько раз без изменения
запроса и настроек.

Benchmark предлагает придумать пять названий приложения для подготовки
разработчиков к техническим собеседованиям и короткие слоганы. Structured Outputs
задаёт формат, а backend независимо от модели проверяет пять требований:

1. Ровно пять вариантов.
2. Название состоит из 1–2 слов.
3. Названия не повторяются.
4. В названиях нет отдельных слов Interview, AI или ИИ.
5. В слогане не больше восьми слов.

Экран показывает «Соблюдение требований: N/5» и накопленное число уникальных
названий для каждой temperature. Различия только в регистре и лишних пробелах
не делают название новым. Счётчик отражает разнообразие; уместность и креативность
оценивает человек, автоматический Creativity Score не используется.

Изменение benchmark-запроса включает свободный режим без формальной проверки
и подсчёта уникальных названий. Кнопка «Вернуть benchmark» восстанавливает исходный
запрос. [Полные условия benchmark](../openspec/specs/temperature-experiment/spec.md)
описаны в OpenSpec.

## Результаты и выводы

Наблюдение пользователя: после **трёх прогонов benchmark** получено по 15 названий
для каждой temperature.

| Temperature | Уникальных названий |
|---|---:|
| 0 | 6 из 15 |
| 0.7 | 13 из 15 |
| 1.2 | 13 из 15 |

Повышение temperature в этом эксперименте заметно увеличило разнообразие.
Однако одинаковые счётчики у 0.7 и 1.2 не означают эквивалентность этих режимов:
трёх прогонов недостаточно для такого вывода. Разнообразие также не доказывает
качество названий или соблюдение всех требований. При T=0 ответы в этих прогонах
не были полностью одинаковыми. По единичным замерам latency нельзя судить
о влиянии temperature на скорость.

## Архитектура

`Android (Compose) → FastAPI (эксперимент и проверка) → OpenAI Responses API`.
API-ключ хранится только на backend.

## Запуск

Подготовьте окружение и `OPENAI_API_KEY` по [инструкции backend](../backend/README.md).
В активированном Python-окружении из корня репозитория:

```powershell
cd backend
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Запустите приложение на эмуляторе по [инструкции Android](../android-app/README.md).
Откройте «Лаборатория температуры», оставьте исходный benchmark и нажмите
«Запустить сравнение». Выполните всего три прогона в одной сессии; сравните ответы,
соблюдение требований и счётчики уникальных названий.
