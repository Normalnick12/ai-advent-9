## Why

Local Android Architecture Assistant должен помогать разбираться в Kotlin/Compose и Markdown-правилах на Mac M1 16 GB с открытой Android Studio. Day 28 подтвердил работоспособность локального retrieval, но нестабильная загрузка Qwen3.5 9B заблокировала A/B, а отдельные ответы остались семантически частичными: требуется ограниченный воспроизводимый выбор конфигурации по качеству, надёжности, времени и памяти.

## What Changes

- Отдельное согласованное дополнение после Day 29 review: offline opt-in compact-evidence-v1 в synthetic driver, без перекрёстных model-generated ID и с runtime-owned status. Это эксперимент schema + минимальных format instructions; live S4/S6 требует отдельного review, прежние контракты и результаты сохраняются.

- Сравнить `qwen3:4b-q4_K_M` и `qwen2.5-coder:7b-instruct-q4_K_M`, зафиксировав установленные digests и эффективные настройки. Qwen3.5 9B остаётся историческим контролем без новых warm-up запусков на первом этапе.
- Ввести технический допуск перед качественным сравнением: компактный запрос должен успешно загрузить модель и завершиться валидным структурированным ответом. Ошибка прекращает ветку; сходный сбой обеих моделей ведёт к отдельному предложению ограниченной диагностики runtime.
- Использовать шесть контрольных сценариев на модель: пять на основе Day 27–28 и один небольшой Compose-сценарий с ViewModel/UI state, StateFlow, collectAsStateWithLifecycle, LaunchedEffect и Coordinator. Сравнивать генерацию на одинаковых заранее выбранных Markdown chunks.
- После выбора кандидата проверить реальную цепочку query embedding → retrieval → generation и оптимизировать по одному фактору: keep_alive, output/context limits, temperature, при необходимости одну адресную правку prompt. Thinking учитывать по capabilities; quantization сравнивать только внутри одной модели отдельным обоснованным опытом.
- Добавить явные настройки extended CLI и безопасные метрики фаз/попыток; различать техническую корректность, смысловую поддержку источниками и практическую полезность. Фиксировать все ошибки, неполные попытки и недоступные измерения.
- Отдельно проверить целевой Mac при наличии устройства и разрешений; Windows не заменяет эту проверку. Допустимый результат исследования — честно установленное ограничение без пригодного профиля.

## Capabilities

### New Capabilities

- `local-assistant-optimization`: контролируемые конфигурации локальной генерации, компактная Android-оценка, этапы допуска/остановки, честные метрики и выбор практического профиля существующей утилиты.

### Modified Capabilities

Нет изменений опубликованных main specs. Базовые local-architecture-assistant и local-architecture-rag остаются в активных changes Day 27–28; новая capability добавляет явный opt-in профиль оптимизации, сохраняя legacy invocation и прежние extended defaults.

## Impact

Будущая реализация затронет существующие `day-27-local-architecture-assistant/` transport, extended prompt/options, CLI metrics и соответствующие tests. `day-29-local-assistant-optimization/` будет содержать обзор дня, компактные синтетические материалы и узкий экспериментальный driver, использующий общую утилиту, без копии CLI/RAG. Корневой README получит ссылку на Day README на этапе реализации.

SQLite, retrieval, source validation, Workspace, embedding profile и исторические результаты не переписываются. Не добавляются агент, MCP, GUI, backend, vector DB или обязательный inference framework. Day 27–28 и их незакоммиченные файлы сохраняются; Day 28 остаётся активным 26/28 с открытыми проверками.

Текущий этап создаёт только planning-артефакты. Реализация, получение моделей и live-вызовы не выполняются; commit/push, archive и запись видео не входят в этот change workflow без отдельного запроса.
