## Why

Репозиторий содержит решения тридцати дней, но не имеет команды, которая объясняет его структуру по актуальной документации и одновременно показывает текущую Git-ветку через MCP. Day 31 объединяет уже проверенные строительные блоки RAG и MCP в небольшой сценарий разработчика; объём ограничен сроком Week 7 до вечера 18 октября 2026 (Europe/Moscow).

## What Changes

- Добавить независимую команду Python CLI `/help "вопрос"` в существующем backend, без HTTP-сервиса, Android UI, памяти и универсального агента.
- Создать `docs/project-structure.md` с описанием реально проверенных компонентов и связей, а также `day-31-developer-assistant/README.md` и ссылку на него в корневом README.
- Закрепить allowlist в `day-31-developer-assistant/corpus.json`. Начальный и полный корпус первой версии: `README.md`, `docs/project-structure.md`, `backend/README.md`, `android-app/README.md`, `scripts/README.md`. Другие Markdown, вложенные docs Week 6, исходники, OpenSpec, локальные файлы и цели Markdown-ссылок автоматически не включаются. Новый документ требует явного изменения allowlist и переиндексации.
- Добавить явное построение отдельного локального индекса, проверку состава, содержимого и конфигурации перед использованием. Переиспользовать функции Week 5, одну structure-aware стратегию и OpenAI `text-embedding-3-small`; не использовать исторические runs, пороги и экспериментальные ограничения.
- Генерировать ответ через OpenAI Responses API с проверяемыми ссылками и дословными цитатами. Честно обозначать отсутствие документального основания; фактическую корректность дополнительно оценивать вручную.
- Добавить локальный read-only MCP tool `get_current_branch`, stdio discovery и настоящий вызов из клиента. Только сервер запускает Git; его результат отображается отдельно от ответа по документации. Ошибка MCP не разрешает прямой Git fallback.
- Добавить необязательный `--trace` с метаданными retrieval и выполненного MCP-вызова без секретов, полного prompt или содержимого окружения.
- Подготовить offline/integration-проверки, четыре live-вопроса (включая отрицательный), ручную оценку и воспроизводимый короткий сценарий видео.

## Capabilities

### New Capabilities

- `developer-assistant-help`: изолированный CLI для вопросов о проекте, разрешённый актуальный корпус, RAG-ответы с проверяемыми источниками и ограниченная диагностика.
- `local-git-branch-mcp`: локальный stdio MCP-контракт текущей ветки, discovery, вызов, проверяемое происхождение результата и явные ошибки без обхода MCP.

### Modified Capabilities

Нет. Контракты и поведение предыдущих дней сохраняются; существующие RAG/MCP-модули служат зависимостями или образцами, а не объектом общего рефакторинга.

## Impact

- Новый небольшой пакет `backend/app/developer_assistant/`, CLI `backend/scripts/day31_help.py`, stdio launcher `backend/scripts/day31_git_mcp.py`, целевые тесты backend; новая зависимость MCP в backend с версией, уже используемой Week 4.
- SQLite и необязательные локальные материалы проверки размещаются в ignored `backend/.local/day31/`. Старые базы, manifests, CLI и API не меняются. Стандартные OpenAI-клиенты и библиотеки backend переиспользуются.
- Документация запуска дополняется в `backend/README.md` и `scripts/README.md`; Day README остаётся кратким обзором. Подробная приёмка и сценарий видео находятся в OpenSpec-артефактах.
- Не входят: Ollama, VPS/Tailscale, объединение Weeks 5/6, новые web/Android-интерфейсы, vector DB, фоновые обновления, LLM rewrite/reranker/judge, автоматическое исправление ответа, история диалога и ремонт старых OpenSpec changes.
- Этот этап создаёт только planning-артефакты. Документы корпуса, runtime, зависимости, тесты и live-запросы относятся к отдельному этапу реализации после review.
