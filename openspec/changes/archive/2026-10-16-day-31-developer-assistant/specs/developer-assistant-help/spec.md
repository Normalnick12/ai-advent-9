## Purpose

Помогать разработчику понимать реальный репозиторий через отдельную CLI-команду: искать по разрешённой актуальной документации, выдавать проверяемые ответы и показывать независимо полученный Git-контекст.

## ADDED Requirements

### Requirement: Isolated help command
Система SHALL предоставлять `/help "вопрос"`, явную команду `index` и необязательный `--trace` в Python CLI существующего backend. Вопросы SHALL обрабатываться независимо, без истории и памяти. Выполнение SHALL не требовать Android, запущенного HTTP backend, Ollama или внешнего MCP endpoint.

#### Scenario: Documentation question
- **WHEN** пользователь вызывает `/help` с непустым вопросом при готовых локальных зависимостях
- **THEN** CLI выполняет поиск, получает Git-контекст через MCP и выдаёт проверенный ответ либо явный статус нехватки контекста
- **AND** Git-результат отображается отдельно от ответа по документации

#### Scenario: Usage and invalid input
- **WHEN** пользователь вызывает `--help` или `/help` без вопроса
- **THEN** CLI показывает справку без MCP и OpenAI запросов
- **WHEN** передан пустой или состоящий только из пробелов вопрос либо неизвестная команда
- **THEN** CLI сообщает об ошибке ввода без платных запросов

### Requirement: Explicit documentation corpus
Система SHALL индексировать только файлы из явного allowlist: `README.md`, `docs/project-structure.md`, `backend/README.md`, `android-app/README.md`, `scripts/README.md` в первой версии. Документ структуры SHALL отражать проверенное устройство репозитория. Система MUST NOT автоматически читать цели Markdown-ссылок, посторонние README, исходники, OpenSpec, скрытые/локальные файлы или секреты. Выбранные файлы SHALL быть обычными UTF-8 Markdown внутри репозитория; переходы за корень, symlinks/junctions/reparse points SHALL отклоняться.

#### Scenario: Exact selection
- **WHEN** строится индекс первоначального корпуса
- **THEN** его источники в точности соответствуют пяти разрешённым файлам
- **AND** добавление постороннего файла или ссылки в Markdown не расширяет корпус

#### Scenario: Invalid or missing source
- **WHEN** allowlist содержит дубликат, запрещённый путь, отсутствующий, нечитаемый или небезопасно перенаправленный файл
- **THEN** построение и ответ прекращаются с явной ошибкой до обращения к OpenAI
- **AND** существующий индекс не заменяется частичным результатом

### Requirement: Explicit index lifecycle and freshness
Система SHALL хранить отдельный индекс Day 31 с идентичностью корпуса, конфигурации и происхождением chunks. Перед `/help` SHALL проверяться актуальность разрешённых документов и allowlist. Отсутствующий, повреждённый, несовместимый или устаревший индекс SHALL приводить к понятной ошибке до платных запросов, без скрытой переиндексации. Повторный `index` для неизменившегося валидного snapshot SHALL завершаться без embeddings-запросов. Ошибка новой сборки MUST NOT повреждать ранее опубликованный индекс.

#### Scenario: Changed document or allowlist
- **WHEN** изменён нормализованный текст разрешённого документа, документ удалён либо явно изменён состав allowlist
- **THEN** `/help` отказывается использовать старый индекс и сообщает о необходимости явного `index`

#### Scenario: Configuration mismatch or corruption
- **WHEN** конфигурация embeddings/чанкинга несовместима либо сохранённые тексты, векторы или метаданные повреждены
- **THEN** индекс не используется для ответа
- **AND** исправление требует явного успешного построения

#### Scenario: Unchanged and failed rebuild
- **WHEN** `index` запущен для неизменившегося корректного snapshot
- **THEN** CLI сообщает, что индекс актуален, не отправляя документы провайдеру
- **WHEN** новая сборка не получает все валидные embeddings либо документы меняются во время сборки
- **THEN** новый индекс не публикуется и предыдущий файл сохраняется

### Requirement: Retrieval grounded documentation answer
Ответ SHALL использовать найденные фрагменты текущего корпуса, а не исторические runs или память модели о проекте. Для содержательного ответа SHALL возвращаться источники с путём, разделом, идентичностью chunk и проверяемой дословной цитатой; отображаемые номера строк SHALL происходить из фактически переданного контекста. Документы и вопрос SHALL трактоваться как данные и не давать права выполнять команды или менять состав корпуса. Недостаточное документальное основание SHALL приводить к явному `insufficient_context`, без выдуманного ответа или декоративных источников.

#### Scenario: Supported answer
- **WHEN** найденные фрагменты содержат основание для ответа
- **THEN** CLI показывает ответ и источники, проверенные относительно именно отправленных модели chunks
- **AND** отдельно показывает Git-контекст из MCP, не выдавая его за цитату документации

#### Scenario: Unsupported question
- **WHEN** вопрос требует сведений, которых нет в найденной документации
- **THEN** корректный ответ обозначает нехватку контекста и не выдумывает проектные факты
- **AND** источники и цитаты для статуса `insufficient_context` пусты

#### Scenario: Invalid citation or incomplete provider result
- **WHEN** модель вернула неизвестный chunk, изменённую цитату, несовместимый путь, невалидную структуру либо незавершённый ответ
- **THEN** CLI сообщает об ошибке проверки/генерации и не отображает candidate как проверенный ответ
- **AND** не делает автоматическую repair-генерацию или повторный запрос

### Requirement: Bounded observable provider usage
Индексация SHALL быть отдельной операцией. Обычный `/help` SHALL делать один запрос embeddings вопроса и не более одной генерации через OpenAI, без скрытого rewrite, judge, reranker и автоматических retries. Лимиты SHALL позволять содержательный ответ и цитаты; сокращение расходов MUST NOT подменять проверку качества. Технический сбой SHALL отличаться от содержательного отказа по недостатку контекста.

#### Scenario: Normal request and failure
- **WHEN** prerequisites, MCP и retrieval успешны
- **THEN** отправляется один query embedding и максимум один запрос генерации
- **WHEN** провайдер возвращает ошибку или timeout
- **THEN** ошибка явно показана, автоматический повтор не производится

### Requirement: Safe optional trace
`--trace` SHALL по умолчанию сохранять JSONL с фактическими индекс/retrieval/MCP-событиями, включая fingerprint индекса, выбранные chunks, ranks/scores и сведения о discovery/вызове инструмента. JSONL SHALL сохранять полные значения и UTF-8 Unicode без обязательного ASCII escaping. Необязательный `--trace --trace-format text` SHALL показывать компактную сводку MCP, количества фрагментов и первых трёх источников с путями/строками/округлённым score, модели/статуса/доступного usage и validation, без длинных идентификаторов и fingerprint. Trace MUST NOT содержать ключи, значения окружения, полный prompt, полные документы или необработанные upstream errors. Диагностика SHALL отличаться от обычного ответа и не добавлять provider-вызовов.

#### Scenario: Trace enabled
- **WHEN** вопрос выполнен с `--trace`
- **THEN** пользователь видит метаданные реально выбранных источников и подтверждённого MCP-вызова
- **AND** количество платных запросов совпадает с выполнением без trace

#### Scenario: Human-readable trace
- **WHEN** вопрос выполнен с `--trace --trace-format text`
- **THEN** stderr содержит компактную сводку без полных hash/chunk IDs/call IDs/PID/fingerprint
- **AND** основной ответ, Git-блок и источники в stdout совпадают с выводом при JSONL trace или без trace
- **AND** `--trace-format text` без `--trace` не включает диагностику

### Requirement: Previous days remain isolated
Day 31 SHALL использовать собственные данные и точки входа. Существующие API, CLI, исторические manifests, индексы и сценарии предыдущих дней MUST NOT изменять поведение из-за добавления Day 31. Day README SHALL содержать только фактические результаты или явное указание на непроведённую проверку; корневой README SHALL ссылаться на него в порядке дней.

#### Scenario: Day 31 setup and execution
- **WHEN** зависимости Day 31 установлены, его индекс построен и выполнен `/help`
- **THEN** данные предыдущих дней не перезаписываются, прежние точки входа сохраняют свои контракты
- **AND** прежний RAG не начинает использовать корпус или настройки Day 31
