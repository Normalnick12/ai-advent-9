## Why

Разработчику нужен небольшой ассистент, который по цели сам исследует несколько исходников и готовит проверяемый Markdown-результат. Существующие RAG-ответы и MCP-сценарии не предоставляют локальный цикл выбора файловых функций с подтверждением конкретного diff перед записью.

## What Changes

- Добавить Python CLI в существующем backend с OpenAI Responses function calling и четырьмя инструментами: `list_files`, `search_text`, `read_file`, `stage_file`.
- Модель выбирает действия и аргументы; runner только проверяет и исполняет вызовы, без маршрута инструментов по сценарию.
- Работать с изолированными копиями трёх разрешённых Python-исходников; разрешать создание или обновление одного Markdown-документа на запуск.
- Разделить подготовку кандидата/diff, явное подтверждение его версии и проверяемую запись с повторным чтением и SHA-256.
- Предоставить два сценария: отчёт об использовании `app.first_rag.core.search` в ограниченном наборе и обновление устаревшего технического описания.
- Сохранять трассу реальных function calls, evidence со строками, проверки границ и результат записи; воспроизводить существенные факты на одинаковых исходных данных.
- Первым шагом реализации проверить реальный обмен function call/output с текущим SDK и моделью до реализации файловой части.

## Capabilities

### New Capabilities

- `project-files-assistant`: ограниченный файловый агент с самостоятельным tool calling, подтверждаемым Markdown-изменением и воспроизводимой проверкой двух сценариев.

### Modified Capabilities

Нет. Поведение существующих дней, API и компонентов не меняется.

## Impact

- Новый модуль `backend/app/project_files_assistant/`, CLI `backend/scripts/day34_files.py` и целевые тесты.
- Manifest, сценарии и исходный Markdown для обновления в `day-34-project-files-assistant/`; runtime-данные в уже игнорируемой `backend/.local/day34/`.
- Краткий Day README, ссылка из корневого README, технические инструкции в README backend и scripts.
- Переиспользовать OpenAI SDK и существующее Python-окружение; не менять общий текстовый LLM-клиент. Новые зависимости не предполагаются; необходимость обновления SDK проверяется первым шагом.
- Не добавлять MCP, embeddings/RAG-индекс, сервер, Android UI, БД, исполнение исходников или универсальный agent framework.
