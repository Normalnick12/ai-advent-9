## Why

Day 32 должен показать автоматическое ревью настоящего Pull Request с опорой на документацию и исходный код проекта. Переиспользование RAG Weeks 5 и 7 позволяет получить проверяемый сценарий PR → отчёт → исправление до окончания Week 7, не меняя поведение Days 1–31.

## What Changes

- Добавить самостоятельный Python CLI и небольшой пакет `backend/app/pr_review/`: получение PR через GitHub REST API, ограниченный RAG в памяти и один структурированный результат OpenAI Responses API.
- Автоматически запускать проверку собственных PR в `main` через два workflow: `pull_request` без секретов и доверенный `workflow_run` из `main`. Форки и Dependabot явно пропускать; содержимое PR никогда не исполнять.
- Использовать пять документов корпуса Day 31, изменённые исходники и очевидные связанные тесты. Искать документацию и код отдельно; diff передавать отдельно; сохранять revision, path и строки каждого источника.
- Проверять evidence IDs и привязку замечаний к изменённым строкам в Python; публиковать один обновляемый PR-комментарий и краткий Actions Summary. Не подменять ошибки или ограничение покрытия заключением «проблем нет».
- Хранить `OPENAI_API_KEY` в Environment `day32-review`, разрешённом только для доверенного запуска из `main`; сериализовать публикации одного PR и проверять актуальный head SHA.
- Провести настоящий live-сценарий с двумя известными дефектами и исправляющим коммитом в отдельном PR, вручную оценить основания замечаний и записать короткое видео. Дефекты не сливать в `main`.

## Capabilities

### New Capabilities

- `automated-pr-review`: безопасный автоматический анализ ограниченного PR с RAG по документации и коду, проверяемый отчёт и обновление для нового SHA.

### Modified Capabilities

Нет. Существующие CLI, API, RAG-контракты, индексы и настройки моделей Days 1–31 сохраняются.

## Impact

- Новые `backend/app/pr_review/`, `backend/scripts/day32_review.py`, целевые backend tests и два файла `.github/workflows/`.
- Новый `day-32-code-review/README.md`; относительная ссылка в разделе «Задания» корневого README; команды и конфигурация в `backend/README.md` и `scripts/README.md`.
- Переиспользуются chunking, embeddings, cosine search, Responses adapter и счётчик input tokens. Новая инфраструктура, Android UI, MCP, Ollama, БД, общий SDK, рекурсивный анализ зависимостей и система хранения артефактов не требуются.
- Внешние действия после реализации: настроить Environment/secret и отдельно разрешить публикацию доверенной реализации в `main`, создание и обновление demo PR. Текущий этап создаёт только planning-артефакты; не разрешает implementation, GitHub mutations, commit или push.
