## Why

Day 33 демонстрирует поддержку пользователей: одинаковый вопрос об авторизации должен получать разные документально обоснованные ответы в зависимости от конкретного обращения. Небольшой DemoStore связывает существующий RAG с настоящим локальным MCP и позволяет проверить нехватку данных без CRM, постоянной памяти и новой инфраструктуры.

## What Changes

- Отдельный FastAPI app в backend-окружении: `POST /support/answer`, Swagger UI, health и просмотр разрешённых FAQ-источников.
- Пять коротких FAQ-документов и три вымышленных тикета: T-101 — временная блокировка, T-102 — истёкший код, T-103 — причина неизвестна. Временные сведения относятся к явно указанному снимку.
- Локальный read-only MCP `get_ticket(ticket_id)` через stdio с настоящими discovery и tool call; основной сервис получает только выбранный тикет и не читает JSON напрямую.
- FAQ embeddings один раз при старте, cosine retrieval в памяти и один Responses API вызов на корректный найденный тикет. Общие правила, наблюдения тикета и инструкции модели разделены.
- Ответ с проверенными evidence ID, восстановленными цитатами, источниками, фактами тикета и компактным подтверждением MCP/RAG. Нехватка сведений и технические ошибки различаются.
- Компактные offline/integration проверки и четыре live-сценария в Swagger UI: T-101 → T-102 → T-103 → T-999.
- Прямой документированный запуск Uvicorn на loopback; `scripts/dev.ps1` не изменяется. Swagger UI позволяет последовательно воспроизвести четыре acceptance-проверки.

## Capabilities

### New Capabilities

- `ticket-support-assistant`: локальная поддержка DemoStore с RAG по FAQ, получением одного тикета через MCP, проверяемым ответом и воспроизводимыми acceptance-проверками через Swagger UI.

### Modified Capabilities

Нет. Контракты и поведение Days 1–32 сохраняются; существующие функции используются без изменения их требований.

## Impact

- Новые данные и краткий обзор: `day-33-support-assistant/`; новая логика: `backend/app/support_assistant/`; stdio launcher: `backend/scripts/day33_ticket_mcp.py`; целевые тесты: `backend/tests/test_day33_*.py`.
- Переиспользуются `document_indexing`, чистые `first_rag` функции, evidence helpers Day 31 и существующий Responses-адаптер. Новая БД, пакетный framework или отдельное Python-окружение не нужны.
- Документация запуска и проверок — в README backend/scripts; ссылка на Day README — в корневом README. В этой planning-фазе изменяются только AGENTS.md и артефакты change.
- Без Android UI, Ollama, VPS, Tailscale, истории чата, CRM и пользовательской аутентификации. Сервис предназначен только для локальных вымышленных данных; отсутствие смешивания запросов не означает доказанную изоляцию пользователей.
- Ориентир реализации и приёмки: 4–6 часов, чтобы оставить время Days 34–35 до вечера 18 октября. Код и live-проверки начинаются только после отдельного разрешения.
