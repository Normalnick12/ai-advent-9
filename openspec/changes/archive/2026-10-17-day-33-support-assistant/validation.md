## Event loop

Синхронные создание embedder, HTTP embed и close выполняются в `asyncio.to_thread`.
Responses использует существующий `OpenAIResponsesLlmClient` и `AsyncOpenAI`.
Тест с heartbeat подтвердил прогресс event loop во время startup embeddings,
query embeddings и ожидания Responses через нормальный асинхронный адаптер.

Во время настоящих запросов независимый HTTP GET `/health` вернул 200 за
2.4 / 1.9 / 1.8 / 1.9 ms соответственно для T-101 / T-102 / T-103 / T-999.
Это измерения одного локального прогона, не performance SLA.

## Четыре live-сценария

Во всех случаях исходный вопрос одинаковый:

Сначала выполнен измеренный HTTP-прогон, затем те же четыре настоящих запроса
через стандартные Try it out / Execute в отрисованном Swagger UI. Повтор для
Swagger проверял пользовательский путь, отображение результата и смену только ID.

Содержательная оценка каждого ответа проведена отдельно от структурной валидации:

- **T-101:** ответ связывает блокировку и пять неудачных попыток с наблюдениями
  снимка 16 октября, 09:00 UTC; 09:15 UTC взято из blocked_until. Совет ждать срок,
  повторить вход с верным паролем и при необходимости восстановить пароль
  подтверждён temporary-lock.md, строки 3–5. Ограничение текущего состояния
  подтверждено строкой 6. Данных T-102/T-103 нет. Формулировка «пока блокировка
  действует» — общее условное правило, не утверждение, что она действует сейчас.
- **T-102:** установлен именно истёкший код, с active/VERIFICATION_CODE_EXPIRED/expired
  в ticket facts; действие — запросить новый и использовать последний код за
  10 минут, не прежний. Основание — expired-code.md, строки 3–4; ограничение
  снимка — строка 6. В Swagger-ответе active также описано в прошедшем времени.
  Причина и рекомендация отличаются от T-101; ожидание разблокировки не назначено.
- **T-103:** ответ не устанавливает блокировку/истечение кода и не делает их
  вероятным диагнозом. Указывает отсутствие состояния и кода ошибки, спрашивает
  точный текст ошибки и этап входа. Это поддержано null-наблюдениями и
  login-diagnostics.md, строки 3–4. Цитаты относятся к уточнениям, а не к выдуманной причине.
- **T-999:** настоящий MCP вернул not_found, после этого query embedding_calls=0,
  generation.calls=0. Сведения другого обращения не подбирались. Источники/LLM
  ответ неприменимы; это штатный отрицательный результат, не инфраструктурная ошибка.

## Ошибки и ограничения

- Windows sandbox helper не запустил shell и встроенный browser runtime.
  Использован разрешённый shell fallback; визуальная проверка выполнена отдельным
  изолированным Chrome без изменения app/политик. Это инфраструктура Codex, не сбой сервиса.
- Локальный NameError подготовки schema исправлен до live-проверок. После этого
  инфраструктурных или смысловых FAIL в просмотренных live-ответах не обнаружено.
- Точная цитата и enum причины не являются полным semantic validator. Свободный
  текст может ошибаться на других запросах; качество произвольных ответов не доказано.
- Top-2 ограничивает охват. В T-101 диагностическая статья оказалась rank 1, но
  применимая статья блокировки вошла rank 2 и была выбрана для ответа. Релевантность
  не равна score, score не устанавливает причину.
- Нет аутентификации: любой локальный клиент может выбрать любой демо-ID.
  Проверена независимость запросов, не авторизация или изоляция реальных пользователей.
- Embeddings FAQ повторяются на перезапуске, память чата отсутствует.
- Генерации и embeddings используют внешний OpenAI; доступность, стоимость и задержки
  зависят от провайдера. /health не подтверждает очередной успешный API-вызов.
- Сырые демонстрационные JSON и screenshots лежат в ignored `backend/.local/day33/`;
  они не добавляются в Git.
