## Context

Мотивация и границы изменения описаны в `proposal.md`. Сейчас `AppRoot` хранит выбранный `AppDestination` через `rememberSaveable`, начинает с Day 02 и рисует внешний `Scaffold` с `NavigationBar`. Каждый урок дополнительно имеет свой `Scaffold` и `TopAppBar`. Три ViewModel создаются в `MainActivity` над `AppRoot`; смена ветки интерфейса их не уничтожает. При этом локальные позиции прокрутки и раскрытые блоки находятся внутри уходящего из композиции экрана.

Design нужен для решения неоднозначностей возврата, владения состоянием и верхними панелями сразу нескольких экранов. Это изменение существующего одного модуля Compose/Material 3, без изменения репозиториев данных и backend. Действующие спецификации Day 03–04 совместимы с каталогом и сохраняются.

## Goals / Non-Goals

**Goals:**
- Разделить список доступных уроков и текущий пункт навигации так, чтобы добавление дня не создавало ещё один элемент нижней панели.
- Сохранить текущие области жизни ViewModel и добавить независимое сохранение локального состояния интерфейса каждого экрана.
- Сделать одинаковым переход назад и убрать вложенное применение общих отступов.

**Non-Goals:**
- Не вводить навигационный фреймворк, DI-контейнер, новый модуль или постоянную базу данных.
- Не переносить экспериментальные данные в сохраняемое состояние Activity и не расширять session-only историю Day 04.
- Не перепроектировать формы и карточки результатов; изменения внутри уроков ограничены заголовками, подписями и сохранением состояния при навигации.

## Decisions

### 1. Двухуровневая навигация Home / Day

`AppRoot` остаётся владельцем текущего назначения, добавляется Home как стартовое значение. Список уроков содержит только запускаемые дни, стабильные идентификаторы, номера, названия и описания. Home не включается в этот список. Открытие карточки меняет назначение; возврат всегда выбирает Home. Отдельный растущий back stack не нужен для этой структуры.

```text
           +------+
           | Home |
           +------+
             |  ^
        open |  | back
             v  |
     +------------------+
     | Day 02 / 03 / 04 |
     +------------------+
```

Системный обработчик назад активен только внутри дня. На Home обработчик не перехватывает выход. Закрытие клавиатуры сохраняет системное поведение. Текущее назначение остаётся сохраняемым при пересоздании Activity; обычный запуск без восстанавливаемого состояния начинается с Home. Восстановление после смерти процесса не обещает восстановления данных эксперимента.

Альтернативы: нижние вкладки сохраняют проблему роста; drawer скрывает выбор дней; Navigation Compose/Navigation3 добавляют зависимости и структуру, пока не необходимые для двух уровней. Пересмотреть выбор можно при появлении вложенных маршрутов или deep links.

### 2. Данные уроков и локальное состояние имеют разных владельцев

Существующие ViewModel остаются на уровне Activity: запрос продолжает выполняться после ухода в каталог и обновляет тот же объект состояния. Экран подписывается на актуальное состояние при возвращении; навигация не вызывает методы запуска.

В `AppRoot` используется один `rememberSaveableStateHolder` с `SaveableStateProvider` вокруг каждого назначения, включая Home. Ключи стабильны и не зависят от отображаемого текста. Сохраняемые состояния прокрутки и раскрытия остаются внутри своего экрана, но получают отдельную область для восстановления после удаления из композиции. Существующие ключи блоков результата сохраняют смысл: новый результат вправе сбросить раскрытие, неизменившийся — восстанавливает его.

Ответы модели, история и агрегаты остаются только в ViewModel; `SaveableStateHolder` хранит небольшие значения UI. Альтернативы: хранение всех экранов одновременно в композиции расходует ресурсы; перенос каждого флага и позиции прокрутки во ViewModel излишне связывает UI с данными; сохранение результатов на диск меняет контракт Day 04.

### 3. Одна верхняя панель на экране

Убрать внешний `Scaffold` с нижней панелью из `AppRoot`. Home и каждый день владеют своим единственным `Scaffold`. Общий небольшой компонент верхней панели урока принимает номер, название и callback возврата. Номер «День NN» отображается меньшим текстом, название переносится по строкам при необходимости. Callback явно передаётся в экран и его content-функцию, чтобы изолированные UI-тесты могли управлять возвратом.

При интеграции проверить цепочку `innerPadding` / `safeDrawingPadding`: системные отступы должны применяться однократно. Альтернатива — единый внешний заголовок над существующими Scaffold — сохраняет дублирование панелей и усложняет отступы.

### 4. Каталог на существующей теме

Новый экран использует `LazyColumn` с ключами идентификаторов дней. Полная ширина карточки нажимается; внутри номер дня, название, описание и декоративная стрелка. Отступы экрана 16 dp, интервал между карточками 12 dp, внутренние отступы карточки 16 dp. Высота определяется содержимым; текст не ограничивается одной строкой. Цвета берутся из текущей Material 3 темы, без отдельной палитры и обязательных тематических иконок.

Для большого окна допустимо ограничить ширину колонки и центрировать её. Многоколоночная сетка не входит в эту итерацию: одна колонка поддерживает длинные названия и увеличение шрифта с меньшим количеством вариантов раскладки.

### 5. Локализация относится к отображению

Русские подписи задаются в Android string resources; имена режимов отображаются через явное соответствие внутреннего enum и ресурса. Новые строки каталога и общие названия берутся из одного источника, чтобы заголовки совпадали с карточками.

Day 02 получает переводы кнопок, переключателей, состояния загрузки, заголовков результатов и метрик. Отображаемые названия режимов: «Свободный», «С ограничениями», «Сравнение». Примеры метрик: «Статус», «Идентификатор запроса», «Выходные токены», «Настройки ответа»; отсутствие значения обозначается «Нет данных». Статическое пояснение вокруг технического значения переводится, само значение остаётся исходным. Остаточные английские подписи Day 03–04 проверяются с сохранением точных строк, заданных их спецификациями.

API enum, имена технических параметров (например, `max_output_tokens`), JSON, ответы и сообщения backend не переводятся. Полная локализация backend не входит в изменение. Альтернатива — замена enum или DTO ради русских подписей — затрагивала бы контракт без необходимости.

## Risks / Trade-offs

- Потеря локального состояния при удалении экрана из композиции → отдельные сохраняемые области по стабильным ключам и сценарий ухода/возврата с прокруткой и раскрытым результатом.
- Повторный запуск или исчезновение результата при переходе → оставить ViewModel над навигацией и проверить возврат во время управляемого незавершённого запроса.
- Увеличенный заголовок или двойные системные отступы → проверить узкий экран, крупный шрифт и область верхней панели после удаления внешнего Scaffold.
- Старые тесты ищут вкладки и ожидают Day 02 при старте → обновить только эти предположения, сохранить проверки экспериментов и добавить точечные проверки новой навигации.
- Последующий запуск после завершения процесса не восстанавливает экспериментальные данные → не вводить постоянное хранение и явно описать границу сессии в README.

## Migration Plan

1. Добавить модель каталога и Home, переключение назначений и области сохранения UI-состояния.
2. Подключить возврат и общие верхние панели ко всем урокам, проверить системные отступы, удалить нижнюю панель.
3. Применить русские подписи, актуализировать затронутые UI-тесты и краткий Android README.
4. Выполнить JVM-тесты, сборку APK и инструментальные сценарии через `scripts/dev.ps1 unit`, `build` и `ui` из PowerShell 7 согласно актуальному AGENTS.md; использовать fake-данные без реальных вызовов OpenAI. Визуально проверить телефон обычной ширины и узкий телефон с увеличенным шрифтом.

Изменения схем данных и backend-деплой не требуются. Откат интерфейсного изменения возвращает прежний `AppRoot` и заголовки без миграции данных. Архивация OpenSpec выполняется после реализации и проверки, а не на этапе подготовки артефактов.
