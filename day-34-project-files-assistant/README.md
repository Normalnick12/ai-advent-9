# Day 34 — Ассистент для работы с файлами проекта

## Суть эксперимента

Python CLI принимает цель и использует OpenAI Responses function calling.
Модель сама выбирает поиск и чтение трёх разрешённых Python-исходников,
затем готовит один Markdown-кандидат с источниками и diff. Работа идёт
в отдельной локальной копии; запись требует подтверждения конкретного candidate ID.

## Что проверяет

- Создание отчёта об использовании поиска и обновление устаревшего описания.
- Настоящие function calls, источники со строками и самостоятельный выбор действий.
- Отсутствие записи до подтверждения, свежесть diff и проверку результата по SHA-256.

## Результаты

Настоящий smoke с `gpt-5.6` завершил function calling за два запроса,
фактическая модель — `gpt-5.6-sol`. Пройдены 86 целевых offline-тестов.
В live-сценарии A подготовлен отчёт за 10 запросов и 9 вызовов инструментов;
источники и исходные хеши проверены. B подготовил обновление за 9 запросов
и 8 попыток инструментов, включая один отказ по размеру чтения. Заданные
ошибки исправлены, полезный раздел сохранён; источники и хеши проверены.
B использовал чтение без `search_text`: это наблюдение остаётся NOT_OBSERVED.
Первоначальная приёмка B была частичной из-за обязательного поиска. После
согласованного пересмотра критерия для обновления документа достаточно
подтверждённого исследования трёх исходников через чтение; A по-прежнему
обязан демонстрировать поиск. По уточнённому критерию оба сценария приняты.
После явного подтверждения пользователя A/B применены штатным CLI:
байты, SHA-256, receipts и неизменность исходников проверены.
Один независимый повтор B на тех же исходных данных сохранил существенные
факты, источники и полезный раздел; search_text снова не наблюдался.
Новый кандидат повтора не применён. В нём сохранено замечание «восемь» вместо
точного «до восьми». Исторический вывод verifier B остаётся partial_review;
пересмотр критерия не означает появления отсутствующего вызова поиска.
Два прогона не доказывают качество любых будущих ответов.
