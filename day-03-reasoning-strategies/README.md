# Day 03 — Сравнение стратегий рассуждения

## Цель

Сравнить четыре prompting-стратегии на одной задаче оптимизации: как меняются
правильность ответа (accuracy), расход токенов, задержка и число API-вызовов.
Проверять решение алгоритмом, независимо от объяснения модели.

## Что реализовано

- Android-лаборатория с запуском всех четырёх стратегий и карточками результатов.
- Детерминированный verifier на backend: проверка ограничений, сумм и оптимальности.
- Метрики tokens, latency и API calls; просмотр инструкции, созданной мета-промптом.

## Эксперимент

| Стратегия | Подход | API-вызовы при успешном выполнении |
|---|---|---:|
| `DIRECT` | Прямой ответ | 1 |
| `STEP_BY_STEP` | Инструкция решить задачу по шагам | 1 |
| `META_PROMPT` | Сначала создать инструкцию, затем решить задачу с ней | 2 |
| `EXPERT_PANEL` | Смоделировать обсуждение аналитика, инженера и критика одним prompt | 1 |

`EXPERT_PANEL` — один вызов с ролевой инструкцией, а не настоящие subagents.

Все стратегии получают одинаковую задачу и базовые настройки: модель,
reasoning effort, лимит выходных токенов и формат финального ответа. Меняется
способ постановки инструкции. Для `META_PROMPT` учитываются оба вызова,
включая суммарные токены и время всей стратегии.

Задача — выбрать набор из восьми фич с максимальной ценностью при бюджете
15 story points, учитывая зависимости и несовместимость фич.
[Полное условие](../openspec/specs/reasoning-strategy-evaluation/spec.md)
зафиксировано в OpenSpec. Полный перебор даёт единственный оптимум:
**A + C + F + G**, стоимость **15**, ценность **29**.
Verifier самостоятельно пересчитывает результат и сравнивает его с эталоном.

## Результаты и выводы

Численные результаты сравнения стратегий в документации не зафиксированы,
поэтому победитель по accuracy, tokens или latency не заявляется.
Число вызовов известно из устройства эксперимента: у `META_PROMPT` их два,
у остальных — один.

При сравнении сначала проверяйте правильность, затем затраты на её получение.
Если стратегии дали одинаково правильный ответ, их различают tokens, latency
и API calls. Более сложная инструкция сама по себе не доказывает прирост
accuracy; задержка отдельного запуска также зависит от сети и нагрузки API.

## Архитектура

`Android (Compose) → FastAPI (стратегии и verifier) → OpenAI Responses API`.
API-ключ хранится только на backend.

## Запуск

Подготовьте окружение и `OPENAI_API_KEY` по [инструкции backend](../backend/README.md).
В активированном Python-окружении из корня репозитория:

```powershell
cd backend
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

<a id="ручная-end-to-end-проверка"></a>

Запустите приложение на эмуляторе по [инструкции Android](../android-app/README.md).
Откройте «Лаборатория рассуждений» → «Запустить все стратегии».
Сравните четыре карточки: правильность, токены, задержку и число вызовов.
Для эталона A + C + F + G ожидается статус «Правильно»; у `META_PROMPT`
можно раскрыть сгенерированную инструкцию.
