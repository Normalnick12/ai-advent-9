# Day 33 — Ассистент поддержки пользователей

## Суть эксперимента

Небольшой сервис поддержки вымышленного DemoStore отвечает на вопросы по FAQ
и конкретному тикету. RAG выбирает документы, локальный read-only MCP получает
только выбранное обращение, OpenAI Responses API формирует ответ с источниками.
Один вопрос об авторизации сравнивается для разных технических наблюдений.

## Что проверяет

- Разные документально обоснованные ответы для блокировки T-101 и истёкшего кода T-102.
- Честный недостаток сведений T-103 и отсутствие генерации для неизвестного T-999.
- Настоящие MCP discovery/tool call, точные цитаты и отсутствие смешивания тикетов.

## Результаты

Реализован отдельный FastAPI app со Swagger UI и индексом пяти FAQ в памяти.
Пройдены 17 целевых offline/MCP integration тестов и 102 регрессионные проверки
переиспользуемых компонентов; повторные и пересекающиеся прогоны не складываются.
Четыре live-сценария прошли через HTTP и Swagger UI: T-101 получил объяснение
блокировки, T-102 — истёкшего кода, T-103 — уточняющие вопросы без диагноза,
T-999 — 404 без query embeddings и генерации. Проверены смысл рекомендаций,
точные цитаты и настоящий MCP. Дополнительно проверены просьба прочитать чужой
тикет и общий вопрос по FAQ. Подробности — в
[отчёте приёмки](../openspec/changes/archive/2026-10-17-day-33-support-assistant/validation.md).

В измеренном HTTP-прогоне ответы модели заняли 4,6–6,3 секунды, неизвестный тикет —
около секунды. Это отдельные наблюдения, а не гарантия скорости или качества
произвольных ответов. Генерация использовала `gpt-5.6` (фактически `gpt-5.6-sol`).

Тикеты относятся к прошедшему снимку `2026-10-16T09:00:00Z`:
это не текущая проверка аккаунтов. Данные вымышленные, сервис без пользовательской
аутентификации рассчитан на loopback. Проверки отдельных запросов не доказывают
разграничение доступа между пользователями.

Зависимости и ограничения описаны в [backend](../backend/README.md),
запуск и проверки — в [scripts](../scripts/README.md).
`OPENAI_API_KEY` задаётся только на backend.
